# 查得到、信得过 · AI 元宝 1024 大侦探

1024 超能 Coding 周末 · 侦探赛道参赛作品骨架。丢一个问题进来，它去检索、给来源分级、交叉比对，然后给出**结论 + 一句话理由 + 可点开的来源**；证据不足就明说「没查到可靠来源」。

同一套引擎可切换五个高复用领域包：政策补贴、资质招投标、健康消费、财务口径、劳动用工。**换行业只换一个 30 行 JSON，不改代码**，详见 [docs/DOMAINS.md](docs/DOMAINS.md)。

零第三方依赖（纯 Python 标准库 + 原生 JS），下载即可跑。

**当前版本 v1.4.0** ｜ `python run.py --version` 看完整版本历史

| 版本 | 做了什么 |
|---|---|
| 1.0.0 | 三层骨架跑通：权威度分级、加权投票、五种终态 |
| 1.1.0 | 语义判定（只判单条）+ 引用逐字校验 + 静态卡与指纹 |
| 1.2.0 | 六个领域包，新增行业只写 JSON 不改代码 |
| 1.3.0 | 多路检索、同源转载、推翻路径、留一检验 |
| 1.4.0 | 三种终态各再进一层：条件差异 / 数字核对 / 补证清单 |

版本号会写进每张卡的 JSON（`card.version`）和静态卡页脚。原因很直接：这套工具主张「同一批输入
永远得到同一个标签」，但门槛、权重、词表改过之后同一个问题就会得出不同的卡。没有版本号，
两张不一样的卡说不清是数据变了还是代码变了。

## 快速开始

```bash
cd detective-agent

# 1. 网页模式（无密钥时自动走离线样例，链路完整可演示）
python run.py

# 2. 命令行模式
python run.py "微波炉加热食物会致癌吗"
python run.py "隔夜菜会致癌吗" --json out/card.json
python run.py "宁波市智能化改造项目最高补贴多少" --domain policy
python run.py "这家供应商的 3C 证书还有效吗" --domain tender

# 3. 接入真实元宝搜索
cp .env.example .env    # 填入 TENCENTCLOUD_SECRET_ID / SECRET_KEY，PROVIDER=wsa
python run.py --provider wsa
```

浏览器打开 `http://127.0.0.1:8765/`。支持 `?q=问题` 直接出卡，方便把单条查证结果分享给评委。

## 三层架构

```
用户提问 + 领域选择
   │
   ├─ 领域层  app/domains/*.json   权威源分层 / 行业线索词 / 语义上下文 / 结论用语 / 免责声明
   │           app/domain.py       加载与套用（不改代码就能新增行业）
   │
   ├─ 检索层  app/query_plan.py     多路查询规划：一句话换几路问法，主动去捞反方与官方口径
   │           app/providers/tencent_wsa.py   元宝搜索 SearchPro（TC3-HMAC-SHA256 手写签名）
   │           app/providers/mock.py          离线样例，无密钥/断网时的兜底
   │           产出：SearchHit（title / url / date / passage / score / authority_level / via）
   │
   ├─ 裁决层  app/semantic.py   语义判定：模型逐条判立场，引用必须逐字可校验
   │           app/stance.py     词典兜底：线索词 + 否定式匹配（含引号剥离与否定式守卫）
   │           app/authority.py  信源分四档：T1 权威一手 → T2 主流媒体 → T3 垂直专业 → T4 UGC
   │           app/sources.py    同源转载识别：文字重合度判定，转载不计独立印证
   │           app/verdict.py    加权投票 → 真 / 假 / 说不准 / 没查到可靠来源（用语由领域包覆盖）
   │                             + 推翻路径：给出这张卡最容易被推翻的三个点
   │
   └─ 表达层  app/llm.py         可选，只润色「一句话结论」，绝不参与打标签
             app/share.py       静态查证卡（自包含 HTML，可分享可归档）
             web/               在线查证卡渲染
```

### 语义判定层怎么保底

| 情况 | 行为 |
|---|---|
| 配置了模型 | 一次请求批量标注所有结果的立场，带 20 字短理由 |
| 模型没配 / 调用失败 | 整体回落词典法（`app/stance.py`），卡片上会写明原因，不静默降级 |
| 某条的引用在原文里找不到 | **只作废那一条**，该条回落词典法，其余照常 |
| 模型返回的 JSON 不合法 | 全部回落词典法，结论照出 |

引用校验的作用：模型很容易顺手「编一句原文」。所以每句引用都要在原文里逐字匹配（忽略标点空白），
匹配不上就直接判这条无效。这一步把「看起来像原文」的幻觉挡在门外，也让每条证据都点得开。

**边界很重要**：模型只判单条证据的立场，不判最终结论。结论永远是裁决层按权重算的。
卡片上每条证据都会标 `语义` 或 `词典`，谁判的一目了然。

### 裁决权重

```
单条证据权重 = 权威度权重(tier) × (0.55 + 0.45 × 相关性) × 时效系数 × 姿态系数
```

| 因子 | 取值 |
|---|---|
| 权威度 T1 / T2 / T3 / T4 | 1.0 / 0.7 / 0.5 / 0.25 |
| 姿态 支持 / 否定 / 存疑 / 仅陈述 | 1.0 / 1.0 / 0.45 / 0（不计票） |
| 时效 ≤30天 / ≤1年 / ≤3年 / 更早 / 无日期 | 1.10 / 1.00 / 0.90 / 0.80 / 0.95 |

判定规则：

| 条件 | 结论 |
|---|---|
| 支持方与否定方权重都 ≥ 0.6 且优势比 < 0.68 | **说不准**，并列出双方原话 |
| 总权重 < 1.0 | **没查到可靠来源** |
| 开放问题最高相关性 < 0.5 | **没查到可靠来源** |
| 优势比 ≥ 0.68 | 优势一方胜出，输出 **真 / 假** |
| 置信度 | 优势比 ± 最高权威档校正 ± 单一站点校正，夹在 20%~95% |

阈值都在 `app/config.py`，改了当场可复现，不需要重训任何东西。

### 三个让「查得准」可以被检验的机制

单路检索天然偏向和用户问法相似的结果，容易只看到同温层证据；转载稿会让同一句话看起来被多家印证。
这两件事都会让结论看起来比实际更可靠。所以除了加权投票，还有三件事：

**1. 多路查询规划（`app/query_plan.py`）**

一次查证自动跑最多 3 路确定性问法（不依赖模型，同一句话每次跑出同一组查询）：

| 模式 | 三路问法 |
|---|---|
| 查真假 | 原句 ／ `核心陈述 + 是谣言吗 官方辟谣` ／ `核心陈述 + 依据 研究 官方回应` |
| 查最新 | 原句 ／ `核心陈述 + 官方 原文 + 当年年份` ／ `核心陈述 + 最新进展` |

结果按 URL 归一去重合并，每条证据都记下自己是被哪一路捞回来的（`via`），
卡片上的「检索路线」面板会显示每路捞回多少条、其中多少条是新出现的。辟谣稿很少用提问式标题，不主动构造反向查询就会漏。

**2. 同源转载识别（`app/sources.py`）**

按 `(权威档, -相关性)` 排序后，用正文前 140 字的**字符三元组 Jaccard 相似度**判定，
≥ 0.55 视为转载，记下原始出处。转载条目的权重 **×0.5**，不计入独立来源数。

这一条直接作用在置信度上：三家网站转同一篇通稿，不应该等于三个独立印证。

**3. 推翻路径 + 留一检验（`verdict._audit_steps` / `_robustness`）**

每张查证卡都附带「想推翻这张卡，可以这样试」，回答「我凭什么信你」：

1. 最高权威那条的原句，逐字回原文核对（引用本身就是可校验的）
2. 指向**对立面**的那条来源，说明它为什么没被采信、翻盘的条件是什么（同侧来源不算反方）
3. 给出本卡最新证据的时间点，提示用更晚的同级来源覆盖它
4. **留一检验**：把权重最高的 3 条证据逐条抽掉重新算一遍，如果结论会翻，直接点名「这张卡是它撑着的」

第 4 条是量化的：权重最高的一条被抽掉后结论不变，说明结论不是靠单条来源撑着；
被抽掉就翻，说明它是支点，必须先核对这一条。比起再给一个置信度百分比，这个信息更能指导人怎么复核。

不是一句「我们很可靠」，而是把这张卡最脆弱的地方自己指出来。

### 三种终态，各自再往前一步

一张查证卡最终只会落在三种状态上：给出了真假、判不出来、没查到。这三种状态下用户真正想知道的，
都不是「结论是什么」，而是「然后呢」。所以每种终态后面都再挂一层：

| 终态 | 只做一步会停在 | 再进一步 |
|---|---|---|
| 真 / 假 | 权重比 + 支撑原句 | **关键数字核对**：同一量纲在不同来源对不上就摆出来 |
| 说不准 | 并排两方原话，让用户自己看 | **条件差异定位**：指出两方说的不是同一件事 |
| 没查到 | 说明为什么不下结论 | **最小补证清单**：再补哪几样就能定性 |

**条件差异定位（`app/conditions.py`）**

「说不准」最没用的版本是「双方都有道理」。真正有用的是说清它们各自加了什么限定条件。
隔夜菜那条样例：

```
否定方：隔夜菜在「冷藏」条件下，亚硝酸盐低于限量标准，不会致癌
支持方：「长期食用」会增加风险，尤其「室温放置超过 4 小时」
→ 一方限定在「冷藏」，另一方限定在「长期食用」
→ 这更像两个不同条件下的两个结论，不宜按同一句话裁决
```

五类条件维度（人群 / 剂量与程度 / 使用场景 / 范围与口径 / 地域），纯词表 + 差集，不依赖模型。
差异必须落在实质维度上才算数，避免「全国 vs 全省」这种不构成分歧的词被判成冲突。

**关键数字核对（`app/numbers.py`）**

用户问得最多的是「多少」，而「多少」最容易因为口径、版本、单位出错。
按量纲（金额 / 百分比 / 期限 / 倍数）归一后并列，跨来源出现不同值就提示。

政策那条样例正好命中：官方写「最高不超过 500 万元」，两个官方来源一致，代办站写「最高可达 3000 万元」。

这一步**不参与裁决**，措辞只说「口径可能不同，请核对」，从不说「矛盾」——哪个数字对，得人点开原文定。
两条硬约束：只有一个来源给出多个值时不报（那是同一份材料在做口径对比），四位年份不当期限。

**最小补证清单（`app/gaps.py`）**

按「这张卡实际缺什么」逐项生成，每条都能直接去补：缺 T1 一手来源、来源集中在单一域名、
只知道是转载但没拿到原文、证据整体偏旧、关键来源没标时间、结论说不准需要双方的适用范围、
没查到需要把问题问细、只有单向证据没有反方。最多给 4 条——多了用户不会做，等于没给。

「敢说不知道」是这套东西最值钱的镜头，但停在认输有点浪费。这一步把它变成一个可执行的下一步。

### 为什么标签不用大模型判定

同一批搜索结果，换一次调用、换一台机器，标签必须一致——这才能被复核。所以标签由加权规则产出，模型只在 `LLM_*` 配置齐全时负责把话说顺。这条边界写在 `app/llm.py` 的注释里，也写在页面底部。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 当前版本、检索层、判定引擎、是否有密钥/模型 |
| GET | `/api/domains` | 领域包列表 |

命令行另有：

```bash
python run.py "问题" --domain policy   # 指定领域包
python run.py "问题" --share           # 生成 out/cards/card-<指纹>.html + .json
python run.py "问题" --json out/a.json # 只存 JSON
```

`provider` 参数可现场切换检索层，录屏时用它证明「骨架不变、检索层可换」。

## 元宝搜索接入要点

- 域名 `wsa.tencentcloudapi.com`，Action `SearchPro`，Version `2025-05-08`
- 入参：`Query`（必填）、`Mode`（0 公开网页 / 1 优质权威垂直信源 / 2 混合）、`Cnt`（10~50）、`Freshness`（d7 / m3 / y2 / 日期区间）、`Industry`（gov / news / acad / finance）、`Site`
- 出参：`Response.Pages` 是**字符串数组**，每个元素还要再 `json.loads` 一次，字段为 `title / url / date / passage / content / site / score / authority_level / favicon`
- `authority_level`（0~5）与 `content`、`Deeplinks` 仅旗舰版返回；标准版靠域名白名单分级，本项目的 `app/authority.py` 两条路都走
- 密钥：`https://console.cloud.tencent.com/cam/capi`；服务开通：`https://console.cloud.tencent.com/wsapi/index`
- 错误码里 `RequestLimitExceeded` 是限频、`ResourceNotFound` 是没开通服务，报错会原样透传到查证卡，不会伪装成「没查到」

## 已知限制

1. 语义判定依赖外部模型，模型不可用时自动回落词典法；词典法对反讽、双重否定、长篇转述会漏判——所以每条判定都附带原文句，漏判能被人一眼看出来，而不会被藏起来。线索词命中前会先做否定式守卫（「没有科学依据」里的「有科学依据」不算支持），但仍不保证覆盖所有中文否定结构。
2. 引用校验是逐字匹配，模型做了合理改写（例如补了主语）也会被判无效并回落，宁可保守。
3. 中文之外的语言线索词未覆盖；语义判定则不受此限。
4. 同一域名最多采信 2 条，避免单一站点刷权重；副作用是单一权威站独占的题目可能因来源不足被判「没查到」。
5. 同源转载识别只看正文文字重合度，同一篇稿被大幅改写后再转载会漏判；反向误判（不同文章共用同一段通稿模板）会把权重压低，但不会翻转结论方向。
6. 多路查询是确定性规则，不是搜索策略学习，问句特别口语化时构造出的第 2、3 路可能召回很差，此时以第 1 路结果为准，不会因为多跑两路就凑数。
7. 条件差异定位靠词表，只覆盖五类常见限定条件；反讽式限定、隐含前提（「本来就该……」「按惯例……」）抽不出来，此时不会误报，但也不会给出提示。
8. 关键数字核对只做量纲归一和并列，不判断哪个数字对，也不识别「同一个词指两个不同口径」（例如两个不同指标的百分比会被并列）。它是有意保守的提示器，不是审计工具。
9. 离线样例（`demo/fixtures.json`）是**演示数据**，不得当作真实查证结果使用，页面会显示「离线样例」角标。
10. `scripts/mock_llm.py` 是本地联调桩，只用来验证语义路径与引用校验，**不是产品代码**。
