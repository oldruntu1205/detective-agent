# 录屏脚本 · 三次真实查询

赛道要求：交一个能打开的作品，外加 **3 次真实查询的录屏或截图**，每次都要有查到的结果和点得开的来源链接。
这份脚本按「拍什么、说什么、录多长」逐条写死，照着走即可。

---

## 一、录制前 10 分钟检查

| 项 | 检查方式 |
|---|---|
| 密钥就位 | `.env` 里 `TENCENTCLOUD_SECRET_ID` / `SECRET_KEY` 已填 |
| 走真实接口 | `.env` 里 `PROVIDER=wsa`；`python run.py --provider wsa` |
| 额度够 | `/api/health` 返回 `"provider": "wsa"`；右上角角标显示「元宝搜索 · 实时检索」 |
| 语义引擎 | `/api/health` 返回 `"stance_engine": "semantic"`；卡片头部显示「语义判定 x 条」；没配模型会是 lexicon，也能跑，只是镜头 D 别演 |
| 结果不空 | 三个问题各跑一遍，确认都有 ≥3 条结果、来源可点开 |
| 窗口干净 | 浏览器缩放到 100%，窗口 1440×900，只留一个标签页，关掉书签栏 |
| 录制方式 | Windows 用 `Win + G` 或 OBS；1280×720 起，建议 1920×1080 / 30fps |
| 时长预算 | 主线三段各 45~60 秒，加分镜头各 20 秒，总长 3 分半以内 |
| 三路查询有效果 | 卡片左下「检索路线」里，第 2、3 路的「新增」列最好不要全是 0；全 0 说明这个话题已经被第 1 路捞干净了，换一个更可能被转载/辟谣的题 |
| 转载标记出现过 | 至少有一次能指到「转载」标签，没有就在镜头 F 里口头说明机制，别硬演 |

**录之前先跑一遍试录**，重点看两件事：来源链接点开是不是真页面（不是 404、不是登录墙），结论有没有因为限频掉成「查询失败」。

## 二、主线三段

### 第 1 段 · 查真假（必录，作品核心能力）

**问题**（选一个真实的、当下有人在传的说法，不要用样例数据）

```
微波炉加热食物会致癌吗
```

**操作**
1. 在输入框敲入问题，回车
2. 等卡片出来，鼠标停在结论标签上 2 秒
3. 缓慢下滚，露出「裁决依据」三条
4. 在「来源证据」里点开**最权威那条**的标题 → 新标签打开原文 → 停 3 秒 → 切回
5. 再点开**反方那条**（如果有），说明为什么没采信

**话术（照读）**
> 我不让它直接回答。先让它去查——元宝搜索返回的每一条结果，先按来源分档：政府、部委、央媒、学术是一档，主流媒体一档，UGC 一档。
> 然后看每条结果是在支持这句话，还是在否定这句话。
> 现在结论是「假」，理由是这一边权重 2.9、另一边只有 0.24——但不是我说了算，权重和每一条的来源都摆在这儿。
> 点开看原文：人民网这条写的是「记者求证多家机构后，微波炉加热食物不会致癌，网传说法不实」。

**要展示的点**：结论 + 一句话理由 + 触发判定的原句 + 来源可点开。

---

### 第 2 段 · 查最新（证明时效与「查询时间」）

**问题**（挑一个答案会变、且你能当场核对的）

```
元宝搜索每月免费调用额度是多少次
```

**操作**
1. 提问 → 出卡
2. 指一下卡片头部的时间戳与耗时
3. 圈出「要点」里的具体数字
4. 点开腾讯云文档原文，让评委看到页面上确实写着这个数字和时间

**话术（照读）**
> 这类问题的答案是会变的，所以它必须带查询时间。卡片上这个时间是本次实际检索的时间，不是模型猜的。
> 答案里出现的每个数字，都能点回到原文；第一条来源是腾讯云官方文档，发布时间也一起带出来了。
> 如果来源里只有一两个月前的老页面，我会在依据里标出来，而且它不会顶着「最新」两个字糊过去。

**要展示的点**：查询时间戳、具体数字、来源是官方文档。

---

### 第 3 段 · 查模糊（证明线索抽取，不是关键词命中）

**问题**

```
那个讲法医的女主剧叫什么
```

**操作**
1. 提问 → 出卡
2. 指着「要点」里并列的两个候选，说明为什么不硬给一个
3. 点开豆瓣/平台页，让评委看到确实存在这部

**话术（照读）**
> 这种问题没有标准答案格式，人会这么问，模型就会硬编一个剧名。
> 我让它把线索拆开：法医 + 女主剧，然后去搜。搜回来的是候选，不是结论——因此我把并列的候选和各自的来源都摆出来。
> 它没有替我拍板，但每一条都能点开核对，这比一个自信的错误答案有用。

**要展示的点**：模糊线索 → 候选并列 → 每条都有来源。

## 三、两个加分镜头（强烈建议录，这是拉开差距的地方）

### 镜头 A · 敢说不知道

```
2027年诺贝尔文学奖得主是谁
```

> 这个问题现在没有答案。它不会编，会直接告诉你「没查到可靠来源」，并且说清为什么：命中的都是背景资料，最高相关性只有 0.42，低于 0.5 的门槛。
> 在这条规则里，说不知道不扣分，瞎编才扣分。

**这一镜是评委明确的加分项，务必录。**

### 镜头 B · 权威源打架时怎么办

```
隔夜菜会致癌吗
```

> 这里出现了真正的冲突：科普中国和联合辟谣平台说不会致癌，澎湃采访的营养科医生和丁香医生说长期吃有风险。
> 两边的权重我都算出来了——1.93 对 1.19，差距 38%。差不到可以定性的程度，所以结论是「说不准」，并且把双方原话并排放在一起。
> 我没让它为了给个痛快答案而硬选一边。判不清的时候说不准，本身就是一种结论。

### 镜头 C（可选）· 检索层可换

```
/api/check?q=...&provider=mock
```

> 这条链路是分层的：检索层换掉，裁决和出卡一层不用改。断网或者额度用完，它能切到离线样例继续跑，只是会挂上「离线样例」的角标，不伪装成真实结果。

### 镜头 D · 语义判定 + 引用可校验（有配模型就录）

**操作**
1. 出一张卡，下滚到「来源证据」
2. 指着每条右上角的 `语义` / `词典` 小标签：**谁判的、怎么判的，全摊在明面上**
3. 点开某条 `语义` 证据的原文，让评委对照「判定理由」和原文那一句

**话术（照读）**
> 立场不是我写死的词表在猜，是模型逐条读原文判的，而且每条都给了一句 20 字以内的理由。
> 但模型有个老毛病：它会顺手编一句「原文」。所以我加了一道硬校验——它摘出来的每一句，都必须能在网页正文里逐字找到，找不到这条判定就作废，自动退回词表法。
> 你在卡片上能看到每条到底是语义判的还是词表兜的。判错能查，判不了会说判不了，这才敢信。

**要展示的点**：`语义` 标签、20 字理由、引用与原文对得上、回落机制可见。

### 镜头 E · 分享一张静态卡

点击右上角「分享卡片」→ 新标签打开自包含 HTML → 直接发出去 / 另存为附件。

> 这张卡不依赖任何外部文件，双击就能看，链接全在。审计一个人给出的结论，比审计一段聊天记录容易得多。

### 镜头 F · 三件让「查得准」可以被检验的事（本轮新增，镜头语言很强）

这一段是整支视频里最能证明「它不是碰巧查对」的部分，三个面板依次指一遍即可，不需要额外操作。

**1. 检索路线**（左下列表）

> 一句话进来，它不会只搜一遍。原句一路，加「官方辟谣」一路，加「依据 官方回应」一路——三路一起跑，专门去捞反方。
> 因为辟谣文章很少用提问的方式写标题，只按原句搜，你永远只能搜到和原句相似的说法。
> 这里能看到每一路捞回多少条、其中多少条是之前没出现过的。多跑两路的价值就在「新增」这一列上。

**2. 转载标记**（来源证据里的琥珀色「转载」标签）

> 这三家网站说的是同一件事，但其中一家是转载人民网的。系统做了正文重合度比对，把它标成转载，权重直接减半，也不算独立来源。
> 因为「三家网站报道」和「三个独立信源」是两回事——很多看起来很确定的结论，就是被转载堆出来的。

**3. 推翻路径 + 留一检验**（「想推翻这张卡，可以这样试」）

> 每张卡下面都有这几步：第一，最高权威那条的原话，你点回去逐字核对；第二，反方那条为什么没被采信、它要满足什么条件才能翻盘；第三，本卡最新证据的时间点，用更晚的同级来源覆盖它。
> 最后一条是算出来的：把权重最高的三条逐条抽掉重算，如果结论会翻，它会直接点名「这张卡是《某某》撑着的」。抽掉都不翻，说明结论不是靠单条来源撑着。
> 我没有说「请相信我」，我把这张卡最脆弱的地方自己指出来了。

**要展示的点**：三路查询的「新增」列、转载标签与权重减半、推翻路径的最后一条（留一检验）。三处都只需滚动，不用点，录起来最省时间。

### 镜头 G · 三种终态，每种都多给一步（本轮新增，最能体现深度）

这一段用三个不同的题连着跑，每个题只停在一个面板上，节奏很快。

**1. 说不准 → 条件差异**（说「隔夜菜会致癌吗」）

> 「说不准」最没用的版本就是告诉你「双方都有道理」。所以我让它再往下看一层：这两方到底在说什么。
> 你看——否定方限定在「冷藏」，支持方限定在「长期食用」。
> 它们其实在回答两个不同的问题。你要问的是哪一种情形？

**2. 查到了 → 关键数字核对**（说「宁波市智能化改造项目最高补贴多少」）

> 这类问题用户要的就是一个数字，数字最容易出错。所以同一张卡里的数字我会横向对一遍。
> 两个官方来源都是 500 万元，这个代办站写的是 3000 万元——差 6 倍。
> 它不会替你判哪个对，只是把这个分歧摆出来，你点开原文自己看。

**3. 没查到 → 最小补证清单**（说「2027 年诺贝尔文学奖得主是谁」）

> 停在这里说「没查到」是合格的，但有点浪费。所以它还会告诉你：还缺什么。
> 缺一份 T1 一手来源、需要把问题问得更具体——这两件事你都能去做。
> 「查不到就认怂」是底线，「认怂之后告诉你怎么才能查到」才是产品。

**要展示的点**：三个面板各一句话，不展开。这一段的说服力来自「三种终态都有下一步」这个结构，不在细节。

## 四、3 分钟路演结构（对照评分权重）

| 时长 | 内容 | 对应得分项 |
|---|---|---|
| 0:00–0:20 | 一句话说清做什么：让 AI 先查再说，说了就有出处 | 创意 |
| 0:20–1:40 | 现场跑第 1 段（查真假），顺手点开两个来源 | 完成度与可用性 / 场景价值 |
| 1:40–2:20 | 跑镜头 A（敢说不知道）+ 镜头 B（冲突裁决） | 创意 / 场景价值 |
| 2:20–2:50 | 讲清一句话：标签由规则产出、模型只负责表达，因此可复现、可复核 | 展示 |
| 2:50–3:00 | 收尾：这套东西能直接长在浏览器插件、客服、家族群里 | 场景价值 |

**要避开的三件事**
1. 不要念技术架构图，评委看的是它查出来的结果对不对
2. 不要用「我们做了一个基于大模型的智能体」这类描述，直接演示它怎么查出结论
3. 不要只演成功案例——「敢说不知道」是这条赛道最值钱的镜头
