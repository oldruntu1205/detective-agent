AI元宝大侦探

查得到、信得过

丢一个问题进来，它去检索、给来源分级、交叉比对， 然后把结论 + 一句话理由 + 可点开的来源一起摆给你。证据不足，就明说没查到。

◆ 标签由规则产出，模型只负责把话说顺。同一批输入，永远得到同一张卡。

问题

AI 敢回答，但不敢作证

搜索类产品已经能「答得像」，但没人能替你回答下一句：这话到底谁说的、能不能点开、换个人跑一遍还一样吗。

✕

没有出处

结论说得斩钉截铁，一条来源都点不开。看起来权威，实际上无法反驳、也无法复核。

✕

分不清轻重

官方文件和养生号文章被同等采信。三家网站转同一篇通稿，看起来像三个独立印证。

✕

顺手编原文

引用看起来像原文，回原文里逐字找，找不到。这类幻觉最难被普通人识破。

◆ 这三件事都不难被检查，只是没人把它做成默认动作。这个作品只做这一件事。
做法

三层，每层只管一件事

检索层

主动去捞反方

一句话换成最多 3 路确定性问法，专门去捞官方口径和辟谣稿。

  • 元宝搜索 SearchPro，TC3-HMAC-SHA256 手写签名
  • 无密钥 / 断网自动走离线样例，链路照样完整
  • 每条记录自己是被哪一路捞回来的
裁决层

算权重，不打分

信源分四档，姿态分四种，加权投票算出真 / 假 / 说不准。

  • 语义判定只判单条，不判结论
  • 引用必须逐字可校验，对不上就作废那一条
  • 同源转载判重，权重减半
表达层

只负责把话说顺

模型可以润色那一句话，但绝不参与打标签。

  • 没配模型也能完整跑，卡片上会写明
  • 静态卡自包含，可分享、可归档
  • 每条证据标注语义还是词典判的
◆ 所以同一批搜索结果，换一次调用、换一台机器，标签必须一致——这才叫可复核。模型只在终点出现一次。

五种终态

最值钱的一屏，是它敢说不知道

点一下看每种终态的判定条件。注意最后两种：没查到 和 查询失败是两件事，不能混。

说不准

◆ 「没查到」不等于「是假的」，也不等于「系统坏了」。三种认输方式必须分得清，否则用户会被自己的工具骗。
可检验性

三个机制，专门用来打自己的脸

单路检索只看得到同温层证据，转载稿会让一句话看起来被多家印证。这两件事都会让结论看起来比实际更可靠。

一次查证自动跑最多 3 路确定性问法，不依赖模型，同一句话每次跑出同一组查询。 查真假走「原句 ／ 核心陈述 + 是谣言吗 官方辟谣 ／ 核心陈述 + 依据 研究 官方回应」。 结果按 URL 归一去重，卡片上的「检索路线」会显示每路捞回多少条、其中多少条是新出现的—— 第 2、3 路新增全是 0，说明这个话题已经被第 1 路捞干净了，不用假装多跑了两路。

取正文前 140 字做字符三元组 Jaccard 相似度，≥ 0.55 判为转载，记下原始出处。 转载条目的权重 ×0.5，且不计入独立来源数。这一条直接作用在置信度上， 卡片上那条会整条降透明度并标注「转载」。

每张卡都附「想推翻这张卡，可以这样试」：回原文逐字核对最高权威那条、指向对立面的来源说明为什么没被采信、 用更晚的同级来源覆盖它。最后一条是量化的——把权重最高的 3 条逐条抽掉重算， 结论会翻就直接点名「这张卡是它撑着的」。比起一个置信度百分比，这个信息更能指导人怎么复核。

三种终态，各自再往前一步

用户要的不是结论，是「然后呢」

点开看真实样例。三步都不参与裁决，只负责把下一步交到人手里。

政策样例正好命中：官方写「最高不超过 500 万元」，两个官方来源一致；代办站写「最高可达 3000 万元」。 措辞只说「口径可能不同，请核对」，从不说「矛盾」——哪个数字对，得人点开原文定。 两条硬约束：只有一个来源给出多个值时不报（那是同一份材料在做口径对比），四位年份不当期限。

隔夜菜那条：否定方限定在「冷藏」，支持方限定在「长期食用」「室温放置超过 4 小时」。 → 这更像两个不同条件下的两个结论，不宜按同一句话裁决。 五类条件维度（人群 / 剂量与程度 / 使用场景 / 范围与口径 / 地域），纯词表 + 差集，不依赖模型。

按「这张卡实际缺什么」逐项生成：缺 T1 一手来源、来源集中在单一域名、只知道是转载但没拿到原文、 证据整体偏旧、关键来源没标时间……最多给 4 条——多了用户不会做，等于没给。

高复用

一个引擎，六个领域包

换行业只换一个约 30 行 JSON：权威源表、线索词、语义上下文、结论用语、时效衰减全部配置化，不改一行 Python。

落地形态

同一套能力，换一个壳就能用

引擎不变，变的只是入口。检索和模型都可以在客户内网，提问不出门，只需要一个出网白名单调元宝搜索。

可现场切换检索层

加 provider=mock|wsa 就能在同一张卡上证明「骨架不变、检索层可换」。

异常原样透传

限频、没开通服务会显示成「查询失败」，不会伪装成「没查到」。这两种错不能混。

界面也是自包含的

日间 / 夜间只靠语义变量切换；粒子层 pointer-events:none，不遮挡任何交互。
